# v0.32.0 candidate: review structured input before sharing

This records the candidate review for three related user outcomes. Refinements and
delivery checks belong to those outcomes. It is preparation evidence, not official
asset verification; see the [release](https://github.com/ax2/zistral/releases/tag/v0.32.0)
for publication status and delivered packages.

## Why these three belong together

A short model task should not require sending a full structured log blindly. Users
need to discover its fields, replace explicitly chosen values locally, and see the
initial request they are about to send. The batch keeps zi focused on bounded input
processing and focused model tasks, with reusable native definitions instead of
persistent conversation history or a general-purpose automation platform.

| User outcome | Native entry point | Important boundary |
| --- | --- | --- |
| Discover structure without sample values | `zi data jsonl-profile` | Paths expose key names; arrays are opaque, no inferred schema. |
| Mask chosen values before disclosure | `zi data jsonl-redact --pointer /token --if-present` | Explicit pointers; no automatic secret detection. Missing-path retention is opt-in. |
| Inspect the first outgoing request | `zi --preview` | No request/tool execution; excludes credential headers, not input or prompts. Later turns and changed context are outside the preview. |

The shared transform tool uses the same bounded operations, but its input has already
been sent to a model. Use the offline commands first when the original values must
not be disclosed. A successful masking run can match zero records; users must review
their chosen paths and resulting data.
